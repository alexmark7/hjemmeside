Collector feedback · field notes

What would you like to tell us?

Feedback is most useful when it describes a real collecting moment: the card you were trying to record, the filter you expected to work, or the point where the collection stopped making sense.

What helps in a bug report or feature note

Keep it short and specific. These four details give the team enough context to act.

  • Card / set involved. Card name, set, and number if you know them.
  • Action taken. The search, filter, add, edit, import, or export step.
  • Expected vs. actual. What should have happened, and what did.
  • OS & app version. Include both once a public release exists.

Leave out passwords, payment details, and home addresses. The phone number field is optional.

Questions people ask before writing

Will this form send an email?

No. The website has no form endpoint configured, so it cannot deliver a message. It validates the fields and prepares the text for copying. Nothing is stored or transmitted by this page.

Can I report a software issue here?

You can write a report in the message field and copy it. The project repository is the best place to check for published issue channels and release updates: project website repository.

Do I have to give my phone number?

No. The phone number is optional. The form only checks its format if you choose to enter one.

What happens when I press “Review message”?

Your browser checks the required fields and formats. If they pass, the page prepares a plain-text copy of your message and offers a copy button. Nothing is sent or stored; the text stays in this tab until you close it.

Can I suggest a feature?

Yes. Feedback about collecting workflows is welcome. If you are suggesting something like statistics or backup merging, check the future development section first — it separates specified features from planned ideas.
